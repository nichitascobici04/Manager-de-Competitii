- Another important aspect is for the 12 features (each one corresponding to a design pattern) to be fully functional, intuitive for the user to use and fully integrated in the frontend UI. The 12 design patterns that should be implemented are Factory Method, Abstract Factory, Builder, Prototype, Flyweight, Facade, Proxy, Bridge, Command, Iterator, Observer and Strategy.
- The Abstract factory will be used for creating the competitions in the Creator page according to its Type and Sport that have different properties.
- The Factory Method will pe used for creating participants on the Participants page according to its Type
- Builder is used also in the Creator page for creating the competition part by part. It will use the informations provided by the Abstract Factory (Type and Sport) meaning those 2 fields should be required for creating the Competition as well as the Name field, in addition the builder will feature Location in which the user will pick one of the existing location in the storage for this the frontend should request the Locations list from the backend and display it in the dropdown list. Another field is Participats similar with locations but the user can pick multiple of them. Builder will be also used in the Edit for a competition in the Manager page. It should be created a page for editing the information of a single Competition where the user can edit any aspect of the Competition via a formAs well You can change the Competition entity to fix the criteria if needed.
- Prototype will be used for creating a duplicate of a competition. It should be created an a duplicate button for each competition from the list in the Manager page. The duplicate feature should copy the entire structure of the competition as a new and independent object.
- Flyweight will be used for referencing to the same location instead of creating a new instance of it. The competition will refer to the same object.
- Facade will be used for providing a simplified, high-level API that orchestrates multiple subsystems related to creating a competitions. This inlcudes automatically generating the rounds and the stages according to the parameters.
- Iterator will be used for iterating through the matches played in a specific location. In the Locations page each location listed will have a link button next to it that leads to a new page for where the user can edit the name of that location and a list of the matches played into a specific location.
- Proxy will be used for providing lazy initialization for competition management.
- Bridge will be used for providing a notification system. It should be implemented a mock notification system that has invitation and result notifications via email and phone.
- Observer will be used for allowing the user to subscribe to a certain competition. At the Manager page, each competition will have a link button called "View" which leads to the view page of that competition. The user will be able to subscribe to a competition by pressing a button on that page. The notifications can be viewed in the Dashboard page in a separate section. Also the view page of the competition will feature a list of all matches generated with facade where the user is able to set and modify score. The user will be able to transfer the modified information with a "Submit Scores" button.
- Command will be used for implementing the Start and Finish commands for a competition. The user will be able to set scores only after they press Start and will be able to do it untile the press the Finish button. Both buttons will be at the top of competition view page.
- Strategy will be user for implementing 2 methods of determnining the winner of the match, 1 for each sport. A football match winner will be able is determnined by which of the score is higher while the tennis match is winner is determined by who has the highest score at most of the sets. In a tennis match each participant will have 3 scores for each set while in a football match each participant will have 1 score for each match.
- All the matches in a competition will be of the same sport
- At matches generation on knockout type competition, each participant will play against another participant once while in the round robin type each participant will play with every other participant in the competition.
- User is not interested which patterns are implemented so he shouldn't know. Do not specify in the frontend the implemented patterns.
- Any other suggestions, ideas, recommandations are welcomed.
